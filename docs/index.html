Below is the complete architectural blueprint of BittyBox's 10 breakthrough mechanics. Every Bitty Box is a self-contained micro-site with its own logic, compound triggers, and cinematic release state.

01 / DUAL-STATE ARCHITECTURE

Dual‑State Micro‑Sites
Alive Mode → Aftermath Mode

Each BittyBox Bitty Box exists in two distinct, independently styled and programmed states:

  • Alive Mode: Normal content, check‑in timer, heartbeat indicators, active personal workspace.
  • Aftermath Mode: Activated state with transformed visuals, unlocked secrets, final letters, or a completely new micro-site.
Competitors only “send something.” BittyBox becomes something.
02 / COMPOUND LOGIC

Multi‑Condition Switches
Compound Triggers

BittyBox rejects brittle single-point triggers. It supports layered compound logic that mirrors real life:

  • Missed scheduled check‑ins
  • Missed heartbeat URL visits (ping endpoints)
  • Failure to enter a secret phrase
  • Device inactivity sensors
  • Secondary Bitty Box not opened in sequence
Creates vault‑grade failsafe logic instead of a single binary trigger.
03 / STATE IMMUTABILITY

Freeze‑and‑Release Mode
Cryptographic Bitty Box Lockdown

Users can “freeze” a Bitty Box into an immutable state:

  • Content locked against tampering
  • Theme and layout crystallized
  • Public or private countdown visible
  • No edits allowed without cryptographic thaw

When the DMS triggers, the Bitty Box “thaws” and executes its payload automatically.

No other DMS platform offers state‑based micro‑site freezing.

Cascading Drops & Multi‑Recipient Payloads

FIELD NOTES & FAQ

Questions before
the countdown?

What exactly is a BittyBox Bitty Box?

A self-contained micro-site with an Alive Mode, an optional Aftermath Mode, and compound trigger rules that determine when the transition occurs. It can contain writing, media, instructions, puzzles, or a full interactive experience with custom styling.

Can I change a Bitty Box after freezing?

Freeze is designed to make the state immutable so that it cannot be altered on a whim or under duress. Before freezing, you can edit freely. Afterward, changing it requires creating a deliberate new version rather than silently altering the one waiting for release.

How does the Burn-After-Trigger execution work?

In Burn-After-Trigger mode, the decryption key is burned in the database as soon as the recipient opens the payload. Once the session ends or is refreshed, the payload is permanently purged and replaced with glitch ashes or an 'Executed' seal.

Can one Bitty Box release to multiple people?

Yes. BittyBox supports multi-recipient payloads and cascading chains (A → B → C). Recipient-specific access and delivery rules can be designed into a Bitty Box before it is frozen.

Is this a guaranteed emergency or legal system?

No. BittyBox is a digital storytelling and contingency tool. Internet access, identity, law, and human circumstances can affect delivery. Keep critical legal wills and safety plans with qualified professionals.

Does the Bitty Box lab run a real switch?

No. It is an illustrative browser preview; it does not monitor check-ins, contact recipients, or trigger a real release.
